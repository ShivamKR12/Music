## Architecture (`KivyMusicApp/`)
- `main.py` is a ~3.5k-line monolith holding `MusicApp(MDApp)`, startup, navigation, theming, and much screen logic — check it before assuming logic lives in the MVC folders. It loads `views/main.kv`, which `#:include`s 20 screen `.kv` files from `views/screens/`.
- Screen Python classes live in `views/screens.py` (mostly `pass` stubs with a few properties); shared custom widgets (Directional horizontal scroll, LazyScreenManager, LyricsScrollView, TrackListItem, PassiveTrailingCheckbox, MarqueeLabel) are in `views/components.py`.
- Playback state/queue: `controllers/player_controller.py`.
- `services/`: `audio_engine.py`, `lyrics_service.py`, `sponsorblock_service.py`, `autoeq_service.py`, `discord_rpc_service.py`, `listen_together_service.py`; multi-source providers `youtube_provider.py` / `spotify_provider.py` / `jiosaavn_provider.py` behind `music_provider_router.py` (`music_provider_base.py`).
- `models/database.py`: SQLite with a thread-shared connection (`check_same_thread=False`). Desktop DB is `KivyMusicApp/music_app.db` (real dev data); Android resolves `user_data_dir`. `track_model.py` must keep `from_dict()`/`to_dict()` for thread/DB serialization.
- `utils/`: `theme_utils.py` (dynamic palette from artwork — heavy, debounce per GEMINI.md §10), `media_utils.py`, `local_audio_utils.py`.

## Commands
- Run: `cd KivyMusicApp && python main.py` (desktop preview is forced 360x640 non-resizable, like the phone).
- Tests are standalone scripts, not pytest. Each sets `KIVY_HEADLESS=1` and `sys.path` itself:
  - Single: `cd KivyMusicApp && python tests/test_lyrics_engine_and_math.py` (14 suites in `tests/`)
  - Full: `cd KivyMusicApp && python tests/run_all_tests.py` — each module runs in an isolated subprocess; exits nonzero on any failure.
- Install: `pip install -r requirements.txt` (repo root; Python 3.13). `ffmpeg` on PATH for full audio decoding.
- Android build (Linux/WSL only): `cd KivyMusicApp && buildozer android debug`. `buildozer.spec` pins `kivymd==2.0.0`, API 33 / min API 21, permissions INTERNET, FOREGROUND_SERVICE, WAKE_LOCK, READ/WRITE_EXTERNAL_STORAGE.

## Gotchas
- Code targets the **KivyMD 2.0 API** (`MDButton`/`MDButtonText`, `style="text"`). Ignore the stale `kivymd>=1.1.1` floor in `requirements.txt` — 1.x component names/styles won't match.
- `main.py` has behavior branches on `KIVY_HEADLESS=1`: instant startup warmup, no transition timers, no background network polling. Tests rely on these paths; don't remove them when "simplifying" startup.
- After any UI change, run the headless suite. `GEMINI.md` §6–§13 defines the invariants asserted there (no widget/property changes off the main thread — marshal with `Clock.schedule_once`; hidden overlays must be `disabled`, not just transparent; explicit bar heights, no `minimum_height`).
- `cache/` is the live yt-dlp download cache (`*.mp3`, thumbnails, `*.json`, `.part` files, `.lrc` lyrics) — not app code; the app does real network downloads by design (GEMINI.md §12 forbids mock content).
- No bundled `fonts/` dir despite the candidate list in `main.py` — `resolve_and_register_system_fonts()` falls back to OS fonts (e.g. `segoeui.ttf` on Windows).
- Commits follow Conventional Commits with scopes, e.g. `feat(theming):`, `refactor(ui):`, `test(desktop):`.
