## Architecture (`KivyMusicApp/`)
- `main.py` is a ~512-line delegating shell: `MusicApp(MDApp)` properties, startup callbacks, KV file loading, and thin forwarding methods only. Business logic lives in single-responsibility coordinators under `app_core/`: `bootstrap.py`, `state.py`, `service_container.py`, `lifecycle.py`, `navigation_coordinator.py`, `settings_coordinator.py`, `playback_ui_coordinator.py`, `lyrics_coordinator.py`, `playlist_options_coordinator.py`, `catalog_coordinator.py`, `search_coordinator.py`. **Do not grow `main.py` again** (`GEMINI.md` §3 & §25).
- `views/main.kv` `#:include`s 21 screen `.kv` files from `views/screens/` (splash, home, search, library, settings, player, analytics, wrapped, notifications, recently_played, album, artist, playlist, browse, podcasts, mood, equalizer, listen_together, auth, favorites, lyrics); the `LazyScreenManager` instantiates screens on first visit.
- Screen Python classes live in `views/screens.py` (mostly `pass` stubs with a few properties); shared custom widgets (Directional horizontal scroll, LazyScreenManager, LyricsScrollView, TrackListItem, PassiveTrailingCheckbox, MarqueeLabel, YouTubeLoadingCircle, PlayerTimelineSlider) are in `views/components.py`.
- Playback state/queue: `controllers/player_controller.py`. Audio: `services/audio_engine.py` orchestrates `decoder_manager.py` -> `dsp_pipeline.py` -> `audio_output.py` on desktop, `AndroidAudioEffectBridge` on Android, with progressive caching in `buffer_manager.py` and hardened extraction in `youtube_extractor.py`.
- `models/database.py`: SQLite is **WAL + single-writer `DatabaseWorker`** (`models/db_worker.py`, daemon thread, `PRAGMA foreign_keys = ON`, `synchronous = NORMAL`, `busy_timeout = 5000`). UI threads use optimistic write-through caches and thread-local WAL read connections (`DB_LOCK` remains only for legacy read helpers). Desktop DB is `KivyMusicApp/music_app.db`; Android resolves `user_data_dir`. `track_model.py` must keep `from_dict()`/`to_dict()` for thread/DB serialization.
- `services/`: expanded set includes `telemetry_service.py`, `recommendation_engine.py` / `recommendation_scoring.py`, `android_media_lifecycle.py`, `android_audio_fx.py`, `logger.py`; multi-source providers `youtube_provider.py` / `spotify_provider.py` (metadata scraping only, resolved via JioSaavn/YouTube) / `jiosaavn_provider.py` behind `music_provider_router.py` (`music_provider_base.py`).
- Android native integration: `android_src/org/shivam/music/MediaSessionBridge.java` + `service/main.py` (p4a `foreground` service) provide MediaSession/MediaStyle notification, Media3/Now Bar metadata, and media-button callbacks; mirrored into Kivy through `services/android_media_lifecycle.py`.
- `utils/`: `theme_utils.py` (dynamic palette from artwork — heavy, debounce per `GEMINI.md` §10), `media_utils.py`, `local_audio_utils.py`.

## Commands
- Run: `cd KivyMusicApp && python main.py` (desktop preview uses 360x640 reference viewport; Android layouts must remain constraint-based/scrollable for varying aspect ratios & insets).
- Tests are standalone scripts, not pytest. Each sets `KIVY_HEADLESS=1` and `sys.path` itself:
  - Single: `cd KivyMusicApp && python tests/test_lyrics_engine_and_math.py` (**25 suites** configured in `tests/run_all_tests.py`)
  - Full headless battery: `cd KivyMusicApp && python tests/run_all_tests.py` — runs each module in an isolated subprocess; exits nonzero on any failure (verifies logic, DB queries & UI geometry only — supplement with real audio, network & `adb` device checks).
- Screen performance benchmark: `cd KivyMusicApp && python -X utf8 tests/benchmark_screen_performance.py new [TAG]` — measurement starts before imports; writes raw JSON + Markdown to `docs/performance/`. Keep every historical record.
- Install: `pip install -r requirements.txt` (repo root; Python 3.13). `ffmpeg` on PATH for desktop audio handling.
- Android build (Linux/WSL only): `cd KivyMusicApp && buildozer android debug`. `buildozer.spec` configures custom `kivymd` / `materialyoucolor` recipes, API 33 / min API 21, `android.add_src = ./android_src`, the `MusicPlayback` foreground service, and permissions `INTERNET`, `ACCESS_NETWORK_STATE`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `WAKE_LOCK`, `POST_NOTIFICATIONS`, `READ/WRITE_EXTERNAL_STORAGE`, `READ_MEDIA_AUDIO`, `VIBRATE`, `BLUETOOTH_CONNECT`.

## Gotchas
- Code targets the **KivyMD 2.0 API** (`MDButton`/`MDButtonText`, `style="text"`). Ignore the stale `kivymd>=1.1.1` floor in `requirements.txt` — 1.x component names/styles won't match.
- Headless branches live in `app_core/bootstrap.py`, `navigation_coordinator.py`, `catalog_coordinator.py`, `services/audio_output.py`, and `recommendation_engine.py` (`KIVY_HEADLESS=1` disables transition timers, background network polling, and real audio output). Tests rely on these paths; don't remove them when "simplifying" startup.
- `services/dsp_pipeline.py` must not import `scipy.signal` at module load — it costs ~2.5 s of cold start. Keep heavy DSP imports lazy/optional.
- After any change, verify according to the 4-tier discipline in `GEMINI.md` §11 & §20–§25 (`tests/run_all_tests.py` covers headless integration & UI geometry; real audio/DSP, extraction, and Android lifecycle require device/runtime verification). `GEMINI.md` §6–§13 defines core UI/thread invariants (no widget/property changes off the main thread — marshal with `Clock.schedule_once`; hidden overlays must be `disabled`, not just transparent; explicit bar heights, no `minimum_height`).
- `cache/` is the live yt-dlp download cache (`*.mp3`, thumbnails, `*.json`, `.part` files, `.lrc` lyrics) — not app code; the app does real network downloads by design (GEMINI.md §12 forbids mock content).
- No bundled `fonts/` dir despite the candidate list in `app_core/bootstrap.py` — `resolve_and_register_system_fonts()` falls back to OS fonts (e.g. `segoeui.ttf` on Windows).
- Commits follow Conventional Commits with scopes, e.g. `feat(theming):`, `refactor(ui):`, `test(desktop):`.
